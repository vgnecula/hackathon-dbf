01 — The problem

An agent can write the environment. The policy will find the seam in it.

Reward climbs to 1.00 in a few hundred steps. Held-out capability does not move. Nothing in the training loop tells you which one you are looking at — the reward signal is the thing that broke.

03 — How it works

Grading happens out of band. The policy's sandbox contains the environment and nothing else — no grader, no held-out tests, no egress to them. It cannot write the number that scores it.

04 — Results

Visible pass rate is what the environment's own grader reports. Held-out pass rate is what the same artefact scores against tests the policy never saw. The gap is the exploit.

05 — Before / after patch

The same attacker suite, re-run against the patched environment: grader moved out of the writable tree, harness pinned by hash, egress denied by default. Each line is one attacker's reward, pre → post.

06 — What we don't catch

Three known holes. None of them are addressed by the current detector set, and a passing rlint report does not imply their absence.

H1

Semantic exploits against LLM-judge rewards

Persuasion, formatting tricks, and answers that read as correct to a judge. No held-out test distinguishes these, and the judge detector only inspects the prompt, not the argument.

H2

Spec error

If the description is wrong, the environment, the visible tests and the held-out tests are wrong together. rlint measures agreement between them; it has no access to intent.

H3

Selection on the detector

The attacker catalogue and the detectors were written by the same people. Recall of 7/8 is recall against known classes — it is an upper bound on the unknown ones, not an estimate of them.
